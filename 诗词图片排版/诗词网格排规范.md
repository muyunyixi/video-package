# 诗词网格排规范（v2.2）

> 用户在稿定设计里做的诗词图片（近体诗红底、宋词蓝底），按这份规范用网格排出图，输出 1440×1920 PNG。只管这类静态诗词图，与视频无关。
> 仓库：`https://github.com/muyunyixi/video-package`，目录 `诗词图片排版/`。**新窗口先读第〇节。**
> v1.0 由 Gemini 整理（以原图实测坐标为基准重排）；v1.1 起（2026-10-25）改为“只给内容就能生成”，参考图只用来识别小黄标和对照偏差；v2.0 起将非固定使用的可选视觉插件独立拆分至《`视觉插件说明.md`》（代码对应 `poemgrid/plugins.py`），主规范只管固定必用的基础网格排底座。修订记录见第十节。

## 〇、给新窗口（先读这一节）

### 1. 开工

1. 把仓库 `muyunyixi/video-package` 拉到会话里（用会话里添加 GitHub 仓库的工具，或 `git clone`），进入 `诗词图片排版/`，`pip install -r requirements.txt`（Python 3.11 以上）。字体直接读仓库的 `公共/汇文明朝体.otf`，不用复制。
2. 用户会给两种材料之一：
   - **文字**：体裁（近体诗 / 宋词）、标题、副标题、正文、要加小黄标或整句变黄的字句、署名。照 `poems/` 里同体裁的例子写一份 TOML：短词眼加小黄标用花括号 `{...}`，整句金句变黄用方括号 `[...]`；宋词上下阕之间写一个空字符串 `""`。若需开启非固定使用的视觉插件（如 `watermark` 大字藏锋底字 + `marginalia` 右上角水印词序背景装帧插件，以及 `<...>` 浅金选中底衬插件），按需查阅并引用同目录下的《`视觉插件说明.md`》。
   - **他在稿定里做好的图**：把图上的文字一字不改地抄进配置，图当参考图（`--ref`）；配置里不写花括号时，小黄标从图上自动识别。
3. `python make_poem.py poems/<名字>.toml [--ref 图]`，输出在 `output/`：PNG 发给用户；`_报告.txt` 里的要点用一两句话告诉他（有没有字贴上小黄标、正文偏右是否超过提醒值、参考图纵向偏差大不大）。

### 2. 和用户怎么配合

- 用户多用语音转文字，同音字会转错（例：“墨迹”被转成“末句”）。先把他的话整理成条目、写出自己的理解，拿不准就问。
- 用户对数值要求很严（他自己说有强迫症）：说位置就给在导出图上量出来的数，不说“看起来差不多”。要改规则时，先用几首诗把影响算出来给他看，他确认了再改。
- 用户的意见是建议：对的做，拿不准的讨论，有更好的方案就提出来。
- 一律用中文。

### 3. 约定

- 诗词原文一个字不改（标点也不改）；署名按用户定的写（现在是 `/muyun.`）。
- 版本号写作 v大.小：小优化、小改动，小版本加一（v1.2 → v1.3）；整体或架构性的改动才加大版本（`公共/整体制作指南.md` 第四节）。
- 改规则：先改本规范（或《`视觉插件说明.md`》，含修订记录），再改代码，出图复测通过后提交推送。
- 提交：首行写成“诗词图片排版：vX.Y 做了什么”，不超过 25 个字；署名 `muyun <19288906+muyunyixi@users.noreply.github.com>`（`git config` 只设在这个仓库）；提交说明里不加 Claude 的署名行（`Co-Authored-By`、`Claude-Session`）。
- 出的图、用户的诗词图都不进仓库，发给用户。
- 本目录与视频无关：做视频的窗口不读这里；这里也不要照 `公共/字体处理规范.md` 去“统一”。两边的网格排和整行边界规则现在是一致的，但纵向排法、小黄标、宋词底块、署名居中是诗词图自己的。

### 4. 用户的原图和本规范的差别（是有意的，不要去“修”规则）

- **水平**：稿定按字格居中，“。”右边的空白也算进行宽，所以原图的正文、标题、横线普遍比本规范偏左约 12 px，署名偏左约 2 px。2026-10-25 用户定按本规范（第四节）。
- 用户以前觉得偏左有好处：抖音右侧有一列按钮会挡字。分析的结论是那列按钮比 12 px 宽得多，偏左 12 px 对遮挡几乎没有帮助；真要避让，应另加一个“整组左移 N px”的参数（署名一起移），图内部的对齐不变。现在没有做，用户没要。
- **纵向和小黄标**：与原图一致（四张参考图偏差在 ±0.35 px 内），参考图主要用来核纵向和识别小黄标。v1.7 起宋词上下阕空行由 1.0 行（`120 px`）改为 0.5 行（`60 px`，上下阕基线差 `180 px`），使纵向间距层级严格递增（同阕 `46 px` < 上下阕 `83 px` < 副标题底块至上阕 `132 px` < 下阕至署名 `158 px`）。
- 有的原图在稿定里整组位置就偏了（第九节第 2 条）。
- 以后用户可能只发文字和要加小黄标的字，不再发图。

### 5. 自由发挥与视觉插件机制

- 固定必用的基础网格排规则全部写在本规范正文中；**非固定使用的可选视觉设计**（插件一：大字藏锋对称暗纹 + 水印词序古籍眉批；插件二：`<...>` 次重点句 12% 浅金底衬 + 70% 底边虚线）统一剥离至独立插件说明包《`视觉插件说明.md`》（代码在 `poemgrid/plugins.py`），需要时在配置中按需引用，不写进主规范正文。
- 不动的底线：诗词原文；网格排（一字一格、墨迹居中于字格）；位置在导出图上量过。

## 一、要点

1. **只给内容就能出图**：标题、副标题、正文、署名、哪几个字下面有小黄标或金句变黄——位置全部由本规范算出，不依赖参考图。
2. **水平**：网格排（一字一格、墨迹居中于字格）；正文按“汉字取字格外缘、标点取墨迹”的两端边界在画布中线居中；全图主左轴 `x0` 固定为七言 16 字标准行居中后的左格（`93.34 px`），对应主右轴固定为 16 字标准行句号墨迹右缘（`x_right = 1440 - x0 = 1346.66 px`）；标题、横线（宋词是副标题底块）左对齐 `x0`（近体诗副标题右对齐横线右端），不随正文每行字数变化；署名按墨迹绝对居中。
3. **纵向**：按稿定设计的文本框叠放（字号 × 行距），宋词上下阕之间的空行按 0.5 行高（`60 px`，基线差 `180 px`）算，整组在画布上垂直居中，再加一个实测校准量。
4. **小黄标与金句变黄**：基础规范内支持 `{...}` 短词眼加小黄标、`[...]` 金句整句改黄字；其余非固定使用的视觉插件见《`视觉插件说明.md`》。
5. **参考图（可选）**：自动识别小黄标在哪些字下面，并逐项列出参考图与标准位置的偏差。

## 二、画布与换算

- 稿定设计的逻辑画布（1x）是 1242×1656（3:4）。字号、行距都按 1x 填。
- 输出 1440×1920。换算倍率 `S = 1440 / 1242 = 80/69`：正文 69 号正好 80 px，1.5 倍行距正好 120 px，没有小数累积。
- 其余字号：主标题 114 → 132.1739 px；横线、署名、宋词副标题 60 → 69.5652 px；近体诗副标题 50 → 57.9710 px。
- 字体只用 `汇文明朝体.otf`（仓库 `公共/` 里那一份；1 em = 1024 单位）。

**颜色**：全系列背景统一为纯正朱红 `#900202`（规避抖音客户端蓝通道屏显盲水印）；正文白字 `#FFFFFF`；小黄标与金句黄字 `#F9C06A`（小黄标在稿定里字号 32，v1.5 由 36 调小）；宋词副标题底块白色 `#FFFFFF`、不透明度 70%（叠在 `#900202` 红底上实际为 `#DEB3B3`），底块上的字与底色一致为 `#900202`。

**体裁视觉区分规范（v2.2）**：
- **宋词**：使用 `70%` 白色镂空副标题框与上下阕 `0.5` 行留白；整句主金句用 `[...]` 变黄，单独一小句写得极妙用 `<...>` 浅金选中框（`18%` 底衬 + `70%` 底边虚线）；背景叠加插件一（右下角 `4%` 大字藏锋 + 右上角 `40×140 px` `35%` 瘦竹新月角标）。

**署名在正文框里**：参考图实测，署名基线永远在正文最后一行基线下方 240.00 px（五张图 239.9–240.3），正好两行正文的行距。也就是说署名和正文在同一个文本框里、中间空一行，署名虽然是 60 号，行高和基线按正文框的 69 号、1.5 倍走。

## 四、水平：网格排

1. **一字一格**：每个汉字、全角标点（含“—”、引号、书名号、括号）占 1 em 字格（正文 80 px）；半角字（署名里的 `/muyun.`）按字体步进占格。汇文明朝体很多字的步进不是整 1024（“了”915、“，”999、“红”1027……），一律不照它。
2. **字在格里按墨迹居中**：`绘制原点 = 字格左缘 + 字格宽/2 − (xMin + xMax)/2 × 字号/1024`；开符号靠字格右边，闭符号靠左边；半角字按步进原样放。同一行共用一条基线。
3. **整行的两端边界**：**行首一律取第 1 个字符的字格左缘**（即使行首是标点符号也按字格左缘方框算，不按墨迹缩进，确保相同字数的两行行末标点上下严格对齐）；**行尾**是汉字取字格外缘，是标点取标点的墨迹右缘（标点右侧的空白不算）。
4. **正文怎么放**（按配置里的 `body` 分行原样排，单行最多 16 个字符）：
   1. 主左轴 `x0` 固定取七言 16 字标准行（14 汉字 +“，”+“。”）居中后的第 1 个字格左缘，恒为 **`x0 = 93.34 px`**（`93.3398 px`）；其对称的主右轴（即 16 字标准行第 16 格句号的墨迹右缘）恒为 **`x_right = 1440 − x0 = 1346.66 px`**（`1346.6602 px`）。主标题首字字格、横线首格、宋词副标题底块左缘固定对齐 `x0 = 93.34 px`；近体诗副标题末字字格右缘固定对齐横线右端 `x0 + 9 × 69.5652 = 719.43 px`。
   2. 正文水平对齐由可选参数 **`body_align`** 控制（支持 `"center"` / `"居中"` 或 `"left"` / `"左对齐"`）：
      - **`body_align = "center"`（近体诗与宋词均默认）**：每一行各自按第 3 条的两端边界在画布中线 `720.00 px` 上水平居中（近体诗各行字数相同，居中后同一列自然严格对齐，七言 16 字首格落在 `93.34 px`，五言 12 字首格落在 `253.34 px`）。
      - **`body_align = "left"`（特殊体裁/词牌需左对齐时可选）**：正文每一行的第 1 个字格左缘直接固定在主左轴 **`x0 = 93.34 px`**（即假设有 16 字正文时第 1 个字格的位置），同一列的字格上下严格对齐。
   - 结果：以汉字开头、“。”结尾的行，比按字格居中右移 13.34 px（“。”画在字格正中，右边空 26.68 px，取一半）。正文本身的首字字格左缘：16 字行 `93.34 px`（与 `x0` 对齐），15 字行 `133.34 px`，14 字行 `173.34 px`，12 字行（五言）`253.34 px`。
   - 看得见的字会略偏右，偏右量 = 首字左边留白的一半：四首例诗 +0.84 – +3.26 px；随机 3000 个汉字在 80 px 字格里的左留白中位 3.98 px，所以一般偏右约 2 px，九成在 +1.0 – +3.3 px。接受它：句末的“。”是个小空圈，视觉上比汉字轻，人眼感觉的中心本来就在墨迹中点偏左一点；而且左轴不随首字跳动。首字特别窄（如“卜”）时偏右会变大，报告里超过 4 px 提醒。
   - 不用“两端都按墨迹”：左轴会随每首诗的首字变（三首近体诗分别是 91.43、91.88、92.50），宋词字数相同的行同一列会错开约 1 px。
5. **署名**：字照第 1、2 条排好（汉字等全角字同样一字一格、格内按墨迹居中，半角字按自身步进），整行再按墨迹（最左一笔到最右一笔）在 720 上绝对居中。署名首尾可能是斜杠、英文、汉字或标点，按字格居中的偏差随内容变（`/muyun.` −2.27、`/muyun` +1.80、`/慕云` +1.09、`/慕云。` −8.97 px），按墨迹总是 0。
6. 所有字转成 SVG 轮廓路径再栅格化，位置精确到万分之一像素，不受浏览器基线取整影响。

## 五、纵向：文本框叠放

1. **行框与基线**：稿定设计把字体外框（`head` 表 yMin −327 … yMax 901）放在行框里上下居中：
   `行框上缘到基线 = 行距 × 字号 / 2 + β × 字号`，`β = (901 + (−327)) / 2 / 1024 = 0.28027`。
2. **叠放**：按第三节的表从上到下，一个元素的行框高 = 字号 × 行距；正文框里，有字的正文行占 1.0 行高（`103.5` 1x 像素 = 输出图 `120 px`），宋词上下阕之间的空行（`""`）占 `empty_line_ratio = 0.5` 行高（`51.75` 1x 像素 = 输出图 `60 px`，即上阕末行到下阕首行基线差 `180 px`），正文末行到署名之间固定空 1.0 行高（基线差 `240 px`）。总高 `H` 求和后，顶部 `top = (1656 − H) / 2`（1x），逐个累加得到各元素基线，再乘 `S` 换到输出像素。
3. **实测校准**（输出像素，加在算出的基线上）：近体诗全部 +1.33；宋词主标题 0、副标题 +0.6、正文与署名 +1.75。
   - 来源：2026-10-25 的四张参考图。近体诗三张（两首绝句、一首七律）每个元素都比公式低 1.0–1.6 px，而且整体一致，是稿定内部的取整或边距；加上校准后，三张图所有元素的基线偏差都在 ±0.35 px 内。宋词只有一张，样本多了再修。
4. **结果**（输出像素）：
   - 近体诗 2 行：主标题 607.65，横线 673.58，副标题 716.71，正文 916.22 / 1036.22，署名 1276.22。
   - 近体诗 4 行（七律）：整组比 2 行时上下各多出 120 px，主标题 487.65 … 署名 1396.22。
   - 宋词 6 行 + 0.5 空行（如《定风波》《临江仙》）：主标题 386.18，副标题 484.01，上阕正文 701.13 / 821.13 / 941.13，下阕正文 1121.13 / 1241.13 / 1361.13，署名 1601.13；副标题底块 y 415.46–504.73。
   - 宋词 4 行 + 0.5 空行（如《浣溪沙》）：主标题 506.18，副标题 604.01，上阕正文 821.13 / 941.13，下阕正文 1121.13 / 1241.13，署名 1481.13；副标题底块 y 535.46–624.73。
5. **宋词副标题底块**：稿定按字自动加的，设置里没有可调的边距。实测它就是字的内容框四周各加一圈边距：
   - 内容框：宽 = 副标题字格总宽；高 = 字体 hhea 的上下界（864 / −160，正好 1 em = 字号），即基线上 0.84375 × 字号到基线下 0.15625 × 字号。
   - 边距 8.5（1x）= 9.855 px：《定风波》量出的四边是上 8.29、下 9.00、左右各 8.36，平均正好 8.50；按 8.5 画，四边与参考图的偏差都在 0.6 px 内。
   - 所以底块 `x = x0`，`y = 副标题基线 − 0.84375 × 69.5652 − 9.855`，宽 = 字格总宽 + 2 × 9.855，高 = 69.5652 + 2 × 9.855 = 89.28 px；字从 `x0 + 9.855` 起排。

## 六、小黄标与金句变黄

1. **形状**：`poemgrid/mark_path.py` 里的矢量轮廓（v1.0 的 MARK_SVG_D，按稿定 2x 图描出，原始轮廓对应字号 36），v1.5 设为字号 32，按 `MARK_SCALE = (40 / 69) × (font_size / 36)` 换算，输出墨迹约 23.9 × 23.9 px（36 字号时约 26.9 × 26.9 px）。
2. **水平**：墨迹左右中心 = 所标字的字格中轴（网格排后也就是这个字的墨迹中心），跟着字走。
3. **纵向**：**墨迹上缘 = 所在行基线 + 9.4 px，固定不动**（宋词、近体诗一样），所以同一行的标一样高，每一行的标离自己那行的距离也一样。
   - 来源：近体诗四张参考图共 5 行、28 个小黄标，同一行的标高度一致，各行平均上缘在基线下 9.04–9.40 px，与标在哪个字下、第几行无关——它跟着行走，不跟着字的墨迹走。用户 2026-10-25 定取 9.4：大多数字和标略微分开，偶尔贴上可以接受。
   - 不因个别字的底边贴上而挪标（挪了的话，每次挪的行、挪的量都不一样）。
4. **间隙报告**：在只有字的图上量每个标正上方、标的宽度范围内那个字的墨迹底边（50% 交点），报告每个标的间隙；负数（贴上）注“贴上”，压进去超过 2 px 的打“←”提醒。只报告，不挪。
   - 四首例诗 28 个标（32 字号）：26 个分开（间隙 +1.16 – +25.42 px），2 个贴上：“却”−1.20 px、“字”−0.17 px。
5. **配置里的两种基础高亮标记**（非固定使用的 `<...>` 浅金底衬等扩展效果见《`视觉插件说明.md`》）：
   - **花括号 `{...}`（短词眼加小黄标）**：在字的正下方放小黄标，适合 2–4 字的词眼，如 `"初拈彩缕{花先老}，春在针尖{不肯开}。"`。
   - **方括号 `[...]`（整句/金句文字直接变黄）**：把括号内的字（含标点）直接染成黄色 `#F9C06A`，不在下方加小黄点，适合核心金句高亮，如 `"[一去几番春草绿，少时只道易重逢。]"`。

## 七、用法

```bash
cd 诗词图片排版
pip install -r requirements.txt          # Python 3.11 以上
python make_poem.py poems/绝句-春天停下了么.toml
python make_poem.py poems/绝句-春天停下了么.toml --ref 参考图.jpg   # 另出参考图对照
```

- 输出：`output/<配置名>.png`（1440×1920，RGB）和 `output/<配置名>_报告.txt`；`--svg` 另存 SVG，`--zip` 另打 zip。
- 配置（TOML）：`mode`（近体诗 / 宋词）、`title`、`subtitle`、`body`（你在列表里怎么分行，出图就怎么分行；宋词上下阕之间写 `""`）、`sign`、`body_align`（可选：不填时近体诗与宋词均默认 `"center"`；可显式填 `"center"` / `"居中"` 或 `"left"` / `"左对齐"`）。可选视觉插件通过 `[plugins]` 表配置，详见《`视觉插件说明.md`》。例子在 `poems/`。
- 改基础模板参数（字号、行距、颜色、校准量、小黄标高度）只改 `poemgrid/template.py`；改可选视觉插件参数只改 `poemgrid/plugins.py`。
- **参考图**：稿定 2x 原图（2484×3312）、重排过的图、聊天软件压缩过的图都可以，必须是完整的 3:4 图（裁过的会被拒绝），统一缩放到 1440×1920 再量。报告第四节逐项列出：每个元素的基线 Δy、左右墨迹边 Δx、实测字号，宋词副标题底块的偏差，每个小黄标的 Δx（标中心 − 字的墨迹中心）和上缘到基线的距离；超过 1 px 的打“←”。
  - 稿定排的图水平方向普遍是 −12 px 左右、署名 −2 px 左右（第〇节第 4 条），属正常；主要看纵向 Δy 和小黄标的偏差即可。
  - 参考图的作用是对照和识别，**出图不跟着参考图走**；某张图如果是故意排得不一样，看报告再决定改配置还是改模板。

## 八、量法与复测

1. **颜色分离**：背景、白字、小黄标三种纯色，用线性解求每个像素里白字和小黄标的覆盖率；抗锯齿边上的混合色也能分开，所以量白字时完全不受小黄标干扰，反过来也一样（红底、蓝底都成立）。宋词副标题在底块色和字色之间求覆盖率；底块本身的四边用“白的覆盖率 ÷ 0.70”的 50% 交点量（每行、每列取中位数做剖面，避开底块上的字和上方的主标题）。
2. **50% 交点**：每列（或每行）取最大覆盖率，在 0.5 处找首末交点，像素 j 看作 j + 0.5 处的采样，相邻像素之间线性插值，得到亚像素的墨迹边。
3. **基线**：由一行的墨迹上下边和这行字在字体里的最高、最低轮廓反推，两个估计取平均。
4. **导出复测**（每次出图自动做）：在导出的 PNG 上逐字量墨迹中心，与算出的位置比。合格：水平 ±0.5 px 以内（实测全部在 ±0.35 px 内，最大的是署名的半角字母）；小黄标的位置误差在 0.1 px 内。竖直方向只作参考：汇文明朝体笔画边缘毛糙，尖细的末端抗锯齿后会缩进零点几像素。

## 九、待确认、已知情况

1. **宋词**：校准量（第五节第 3 条）、底块边距 8.5、正文每行居中，都只来自《定风波》一张图；v1.7 起将上下阕空行由 1.0 行调优为 0.5 行（若拿旧版空 1.0 行的原图做 `--ref` 对照，主副标题与上阕会偏上 30 px、下阕与署名会偏下 30 px，属规则升级的预期差异）。
2. **稿定里的“居中”不一定等于看得见的字居中**：2026-10-25 第二张《绝句·春天停下了么》（JPG）和第一张（PNG）文字完全相同，却整组向左偏了约 12.6 px——主标题 −12.1、横线 −12.6、正文第二行 −12.6，连没有中文标点的署名也 −12.6（另外三张图署名中心都在 720.0–720.2）；整图互相关也是 −13 px。同样的字、同样的标点，排出来的宽度不会变，所以不是标点空白算没算的问题，是整组在画布上的位置。用户在稿定里看是居中的；可能是被居中的选区里含了看不见的文本框（空文本框、底部透明文本框）往右伸得更远，或者软件本身的问题。本工具按内容算位置，不受影响；拿这类图做参考图时，报告里整组的 Δx 会一起再偏。
